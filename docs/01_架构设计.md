# 01 架构设计

## 目标架构

```text
员工微信
    ↓
agent-wechat
    ↓
CF Gateway（规划）
    ↓
Hermes Agent
    ↓
Skills
    ↓
企业系统
```

返回结果沿调用链反向发送到员工微信。V1 只验证 agent-wechat 入口层；图中其余
组件的出现表示目标边界，不表示已经部署或接通。

## 组件职责

| 组件 | 职责 | V1 状态 |
| --- | --- | --- |
| agent-wechat | 微信账号、消息收发、联系人/聊天管理、媒体入口、事件转发 | 部分能力 **Verified** |
| CF Gateway | 鉴权、身份映射、协议适配、限流、幂等、重试、审计和路由 | **Pending** |
| Hermes Agent | 理解、决策、Agent 编排和上下文管理 | **Pending** |
| Skills | 经授权执行可复用企业能力 | **Pending** |
| 企业系统 | ERP、知识库和其他业务数据与动作 | **Pending** |

## agent-wechat 边界

agent-wechat 可以暴露微信侧数据和动作，但不应基于消息内容做 AI 推理，不应直接
持有 ERP 等企业系统的高权限凭据，也不应实现企业审批或业务规则。图片和文件
属于入口范围，但发送能力当前仍是 `Pending`，不能宣称完整支持。

## 集成原则

- CF Gateway 是唯一规划中的企业集成入口，负责把上游 API 变化隔离在适配层。
- Gateway 不应依赖微信 GUI 登录状态，而应以 agent-wechat session/API 状态为准。
- 登录初始化必须通过 `/api/ws/login` 完成，并以 `login_success` 和 `userId` 作为
  可调用业务 API 的前置条件。
- 所有写操作都应在 Gateway 增加调用方身份、授权、幂等键、超时和审计记录。
- auth-token 仅用于 agent-wechat 接口认证，不能替代企业用户身份和业务授权。
- 消息、联系人和媒体属于敏感数据；日志与监控不得记录完整正文或 token。

## 当前数据流

V1 已验证的直接调用路径为“受信任管理端 → agent-wechat REST/WebSocket → 微信
客户端”。CF Gateway、Hermes Agent 和 Skills 尚未接入。接口清单见
[api.md](api.md)。

## Known Issue

VNC 是登录和诊断通道，不是业务 API。其 interactive x11vnc 状态存在启动不稳定
问题，验证环境通过额外 systemd 修复服务恢复；调用链设计不能依赖 VNC 可用性。
