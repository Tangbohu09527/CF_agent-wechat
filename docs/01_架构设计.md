# 01 架构设计

> [!WARNING]
> 本文目标架构仅适用于 `feat/forced-qr-login@9cb7163` 及其后续合入版本。
> 本文审计的 `main` 代码基线 `96264e2` 不含这些生命周期入口；目标流程已完成自动化验证，
> 但真实扫码与 Debian 启动窗口仍未完成 CFserver 实机验证。

## forced-QR 目标架构

```text
CFserver Host / Docker
  |
  +-- cf-agent-wechat container
  |     +-- internal Xvfb
  |     +-- /usr/bin/wechat
  |     +-- agent-server :6174
  |     +-- /data              <- runtime/data
  |     +-- /home/wechat       <- runtime/wechat-home
  |     +-- /data/auth-token   <- 独立只读 Token
  |
  +-- external network: cf-internal
        +-- CF_agent-gateway Poll Worker
        +-- CF_agent-gateway Delivery Worker
              +-- Hermes and downstream systems
```

生产依赖容器内 Xvfb，不依赖 Host X11。`ENABLE_VNC=0`，x11vnc、websockify、noVNC、
XFCE 与 RDP 不在生产链路。

## 组件与所有权

| 组件 | 职责 | 所有权边界 |
| --- | --- | --- |
| `cf-agent-wechat` container | 承载 Xvfb、WeChat、agent-server | 本仓库管理 Compose 与生命周期 |
| `/usr/bin/wechat` | 维持微信客户端会话 | 上游镜像能力，本仓库验证真实进程身份 |
| agent-server `:6174` | 提供健康、认证、聊天、消息和发送边界 | 上游 schema，不是本仓库稳定公共 API |
| Runtime | 当前 `data` 与 `wechat-home` | 每次 fresh QR 新建 |
| Archive | 保存旧 Runtime 和脱敏 manifest | 只归档，不恢复；按敏感资产处理 |
| Token | Agent API 认证 | 独立只读挂载，不属于 Runtime/Archive |
| Gateway Controller | 管理 Poll/Delivery Worker | 位于 `CF_agent-gateway`，不属于本仓库文件 |
| `start-qr-login.sh` | 编排 Agent 生命周期与 Controller 调用 | 不拥有 Gateway 内部实现或数据模型 |

## 生命周期编排

```text
Operator
  -> Controller contract/stop
  -> stop and remove old Agent container
  -> atomically archive old Runtime
  -> create fresh Runtime
  -> start Agent with restart=no
  -> verify Docker health and Agent API
  -> verify stable /usr/bin/wechat PID:start_time
  -> POST login newAccount=true
  -> render QR in current SSH TTY
  -> phone scan and confirm
  -> verify auth + non-empty chats + one messages read
  -> Controller start/status
  -> ready + Token Contract + Poll/Delivery healthy
```

Controller 管理 Gateway Worker，不管理 Agent 容器。`start-qr-login.sh` 负责编排双方的
先后关系，但 Gateway 的 Message、Admission、Checkpoint、Dispatch、Response 与
Delivery Receipt 仍归 `CF_agent-gateway`。

## Three readiness layers

1. **Agent API health**：Docker health 只调用 `/health`，证明 Agent API 可达。
2. **WeChat runtime readiness**：真实进程身份稳定、auth `logged_in`、chats/messages
   可读。
3. **Gateway readiness**：`ready=true`、Token Contract valid、Poll/Delivery healthy。

任何单层都不能替代完整生产在线判定。`status.sh` 输出 11 个状态项，并按不同失败类别
返回非零退出码。

## Network and storage

- Agent container port 为 6174，Host 只绑定 `127.0.0.1`。
- Gateway 通过 external `cf-internal` 和 alias `cf-agent-wechat` 访问。
- `cf-internal` 不是本项目可随意删除的网络。
- Runtime：`/srv/storage/cf-agent-wechat/runtime`。
- Archive：`/srv/storage/cf-agent-wechat/session-archive/<UTC timestamp>`。
- Token：`/srv/storage/cf-agent-wechat/secrets/auth-token`，挂载到 `/data/auth-token:ro`。

## 健康与登录是不同状态

容器 `healthy`、Auth `logged_in` 或单个 Worker healthy 都不能单独证明生产在线。
判断必须覆盖 `status.sh` 的 11 项输出：Container、Docker Health、Agent Server、
WeChat Process、Auth、QR Runtime Mode、Message API、Gateway Runtime Ready、
Gateway Token Contract、Gateway Poll Worker Health 和 Gateway Delivery Worker Health。

Agent/Runtime 层的问题由本仓库处理；Controller ready、Token Contract 与 Poll/Delivery
health 是 Gateway Runtime Contract 交界面；Gateway 内部调度与 Hermes 属于外部边界。
## Restart boundaries

- CFserver 或 Agent 重启：Agent 保持停止，必须 fresh QR；Archive 不复用。
- Gateway-only 部署：不重启/删除 Agent 时，已观察到 Session 保持。
- AI/Hermes Host 重启：CFserver 与 Agent 未重启时无需 fresh QR；下游恢复属于外部边界。
- Host reboot 后 Gateway Worker 可能已运行，必须显式 Controller stop/confirm。
