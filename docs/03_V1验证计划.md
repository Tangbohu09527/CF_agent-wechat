# 03 V1 验证计划

## 目标

验证 agent-wechat 能否作为企业 AI 系统的微信入口，并验证 CF Gateway 与 Hermes
在 Staging 环境中的文本消息闭环。V1 不验收图片理解、附件传递、文件处理、OCR、
压缩包解析、企业知识库、Skill 自动执行或生产环境自动部署。

## 阶段状态

agent-wechat 的基础部署、登录状态、文本消息读写、`txt`/`zip` 文件入口识别、
群聊、引用上下文、合并转发消息外层识别和重启恢复已经完成验证。V1 Staging 已
通过 Gateway Polling 完成身份与权限准入、AIThread、Hermes 调用和微信文本回复
回传。实时 WebSocket 事件和系统级媒体、文件能力仍属于后续阶段。

## 后续验收要求

### 图片与文件

至少覆盖私聊、群聊、类型/大小限制、失败返回、重复发送、超时和重启后的临时文件
清理。当前只验证了 agent-wechat 对 `txt`、`zip` 文件的接收、识别和 Base64 获取，
不得将其写成 Gateway 附件传递、系统文件处理、压缩包解析或所有图片/文件能力。

### 合并转发消息

群聊中的微信“合并转发聊天记录”已验证可读取外层消息、发送者和标题。通过 media API
获取内部内容时返回 `type=unsupported`。该结果应表述为“外层识别已验证，内部解析
待增强”，不得宣称已经支持内部聊天记录展开。

### WebSocket 实时事件

当前已经确认连接可以建立。后续至少记录连接认证、重连、心跳、订阅条件、事件
类型、事件 ID、顺序、重复投递、断线窗口和背压行为。只有实际接收微信新消息事件
后才能标记为 `Verified`；在此之前 Gateway 继续使用 Polling。

### CF Gateway 与 Hermes

V1 Staging 文本闭环已经验证。后续重点是媒体契约、错误映射、超时、重试、幂等、
限流、审计、生产可靠性，以及将群聊上下文从当前 whole-room 聚合修正为目标
`bot + group + sender` 隔离。

## Known Issue 验收

- VNC 默认 interactive x11vnc 状态不稳定；需验证修复服务在冷启动和重启时均生效。
- 仓库重启策略与已验证主机不同；需在正式配置变更后重新执行宿主机重启测试。
- 微信 GUI 登录和 agent-wechat session 是不同状态源；登录测试必须以
  `/api/status/auth` 和业务 API 可用为准。
- Docker 重启后微信客户端需要重新登录；容器、health 和 VNC 恢复不能作为微信
  在线状态的替代证据。
- Gateway V1 whole-room 群聊上下文是已知实现偏差，不得写成最终模型。

## 结果更新规则

每次验证记录镜像 tag、digest、操作系统、Docker/Compose 版本、步骤、预期结果、
实际结果和遗留问题。失败或未执行的项目只能标记为 `Pending` 或 `Known Issue`。
单体入口能力和系统端到端能力必须分别记录。
