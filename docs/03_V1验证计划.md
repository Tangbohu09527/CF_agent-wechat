# 03 V1 验证计划

> **历史实验（已废弃、非当前生产方案）**
>
> 本文是早期 V1 验证计划快照，不代表当前生产待办或运行步骤。涉及 VNC、noVNC、
> x11vnc、XFCE 或旧 Compose 的内容只描述当时实验环境。当前状态见
> [验证总览](validation.md) 和
> [2026-08-13 生产验证](validation/2026-08-13-cfserver-production.md)。

## 当时目标

该计划用于验证 agent-wechat 能否作为企业 AI 系统的微信入口，并记录外围调用方的
文本联调边界。图片理解、附件传递、文件处理、OCR、压缩包解析、企业知识库、
Skills 和生产自动部署不在当时 V1 验收范围。

## 当时阶段状态

当时实验已覆盖基础部署、登录状态、文本消息读写、部分文件入口识别、群聊、引用
上下文、合并转发消息外层识别和重启恢复。外围调用方曾完成文本联调；其内部身份、
权限、线程和 AI 调度细节不属于本项目文档范围。

## 当时后续验收项

### 图片与文件

计划覆盖私聊、群聊、格式、大小限制、失败返回、重复发送、超时和临时文件清理。
当时只验证了 agent-wechat 对 `txt`、`zip` 的接收、识别和数据获取，不能外推为
上层附件传递、系统文件处理或所有图片与文件能力。

### 合并转发消息

当时已验证外层消息、发送者和标题；media API 对内部内容返回不支持。准确边界是
“外层识别已验证，内部解析待增强”。

### WebSocket 实时事件

当时只确认连接能够建立，没有观察到微信新消息事件。事件类型、顺序、重连、重复
投递和背压均未完成验证。

## 当时 Known Issues

- 历史实验环境的 interactive x11vnc 状态不稳定；该路线现已废弃。
- 当时实验室 Compose 的重启策略与验证主机不同。
- 微信 GUI 登录和 agent-wechat session 是不同状态源。
- 容器、health 和历史 VNC 恢复不能替代微信在线状态证据。

当前生产固定 `ENABLE_VNC=0`，不再执行上述 VNC 验收。当前登录以
`status.sh`、`login.sh` 和认证状态复核为准。
