# 03 V1 验证计划

## 目标

验证 agent-wechat 能否作为企业 AI 系统的微信入口，并为 CF Gateway 契约设计
提供事实依据。V1 只覆盖入口层，不验收 AI 推理、Skills 或企业业务流程。

## 阶段状态

V1 基础部署、登录初始化、文本消息读写和重启恢复已经完成验证。媒体能力、实时
事件和 Gateway 集成转入后续阶段。

## 验证范围

| 范围 | 验收项 | 状态 |
| --- | --- | --- |
| Deployment | Debian、Docker、Compose、digest、token、健康检查 | **Verified** |
| Runtime | `unless-stopped`、宿主机重启、agent-wechat、VNC 恢复 | **Verified** |
| Login | `/api/ws/login` → `login_success` → `userId` | **Verified** |
| Read API | 联系人、聊天、消息读取 | **Verified** |
| Send API | 私聊和群聊文本发送 | **Verified** |
| Media | 图片发送、文件发送 | **Pending** |
| Events | `/api/ws/events` 实时消息事件 | **Pending** |
| Integration | CF Gateway / Hermes Agent | **Pending** |

详细证据边界见 [validation.md](validation.md)。

## 后续验收要求

### 图片与文件

至少覆盖私聊、群聊、类型/大小限制、失败返回、重复发送、超时和重启后的临时文件
清理。当前不得写成支持所有图片或文件能力。

### WebSocket 实时事件

至少记录连接认证、重连、心跳、事件类型、事件 ID、顺序、重复投递、断线窗口和
背压行为。只有实际接收消息事件后才能标记为 `Verified`。

### CF Gateway

至少定义请求身份、授权、消息契约、错误映射、超时、重试、幂等、限流、审计和
敏感数据脱敏。与 Hermes 的端到端调用尚未验证。

## Known Issue 验收

- VNC 默认 interactive x11vnc 状态不稳定；需验证修复服务在冷启动和重启时均生效。
- 仓库重启策略与已验证主机不同；需在正式配置变更后重新执行宿主机重启测试。
- 微信 GUI 登录和 agent-wechat session 是不同状态源；登录测试必须以
  `login_success` 和 API 可用为准。

## 结果更新规则

每次验证记录镜像 tag、digest、操作系统、Docker/Compose 版本、步骤、预期结果、
实际结果和遗留问题。失败或未执行的项目只能标记为 `Pending` 或 `Known Issue`。
