# 04 二开规划

## 原则

二开优先新增 CF Gateway 等外围服务，不在 agent-wechat 核心中承载 AI 推理、
ERP 操作或企业业务逻辑。所有规划项默认是 `Pending`，完成实际验收后才能改为
`Verified`。

## V1.1：部署基线收口

- 将已验证的 `restart: unless-stopped` 策略纳入配置评审。
- 将 `docker/fix-vnc.sh` 和 `cf-wechat-vnc-fix.service` 纳入受控版本管理。
- 完成备份恢复、token 与数据库联合恢复、升级回退演练。
- 补齐持续运行、磁盘增长、日志脱敏和告警验证。

## V1.2：入口能力补充

- 验证图片收发。
- 验证 API 文件发送，并扩展 `txt`、`zip` 之外的格式和大小边界。
- 调查 `/api/ws/events` 已连接但未推送新消息的问题，再验证断线重连和重复事件处理。
- 固化文本、文件、群聊和引用消息的请求/响应与错误契约。

## V2：CF Gateway

- agent-wechat 协议适配与版本隔离。
- 企业用户身份映射和最小权限控制。
- 幂等、限流、超时、重试、熔断和错误映射。
- 消息、调用方、授权决策和执行结果审计。
- 敏感字段脱敏以及日志、指标、Trace 规范。

## V3：Hermes 与 Skills

- 定义 Gateway 与 Hermes Agent 的稳定契约。
- 通过明确授权的 Skills 连接企业系统。
- 对高风险动作增加确认、审批、回滚和审计。
- 建立端到端测试，确保入口层不绕过 Gateway 直接操作企业系统。

## Known Issue

VNC 修复和自动重启在验证主机有效，但尚未完整进入仓库部署基线。该差异应在继续
扩展业务能力前优先收口，否则新环境不能稳定复现 V1 结果。
