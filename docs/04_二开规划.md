## 当时原则

agent-wechat 只承担微信入口，不承载 AI 推理、ERP 操作或企业业务逻辑。外围调用方
和 AI 服务的内部实现属于其他项目，不在本仓库展开。

## 当时规划基线

早期 Staging 曾完成外围调用方与微信入口之间的文本联调。该历史结论只覆盖文本，
不证明媒体、文件、Skills、生产部署或长期可靠性已经完成。

## 当时入口规划

- 将实验环境的重启策略纳入评审。
- VNC 修复资产曾计划纳入版本管理；该路线现已废弃。
- 完成数据、微信用户目录和 Token 的联合备份恢复演练。
- 补齐持续运行、磁盘增长、日志脱敏和告警验证。
- 验证图片收发和 API 文件发送。
- 调查 `/api/ws/events` 未观察到消息事件的问题。
- 固化文本、文件、群聊和引用消息的接口边界。

## 外围系统边界

当时规划包含 Gateway、AI 服务和 Skills 的后续工作，但这些系统的身份、权限、线程、
调度、重试和审计实现均不属于 `CF_agent-wechat`。本仓库只记录调用关系：Gateway
通过 `cf-internal` 访问 `http://cf-agent-wechat:6174`。

## 历史限制

- VNC 修复是当时实验结论；该路线已废弃，不属于当前生产部署基线。
- agent-wechat 的 `txt`、`zip` 入口识别不等于系统文件处理或压缩包解析完成。
- 图片、API 文件发送和实时消息事件没有由该规划证明为可用。

当前生产状态和待验证范围以 [验证总览](validation.md) 为准。
