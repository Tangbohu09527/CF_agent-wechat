# 04 二开规划

## 原则

二开优先在 CF Gateway 等外围服务实现，不在 agent-wechat 核心中承载 AI 推理、
ERP 操作或企业业务逻辑。已完成项以实际验证为准；未完成项必须保持 `Pending`。

## 当前基线

V1 Staging 已完成 Gateway Polling、身份解析、权限准入、Employee Workspace、
AIThread、Hermes 文本调用、响应回传和 self echo 防回环。该结论只覆盖文本消息，
不代表媒体、文件、Skills 或生产自动化已经完成。

## V1.1：部署基线收口

- 将已验证的 `restart: unless-stopped` 策略纳入配置评审。
- 将 `docker/fix-vnc.sh` 和 `cf-wechat-vnc-fix.service` 纳入受控版本管理。
- 完成备份恢复、token 与数据库联合恢复、升级回退演练。
- 补齐持续运行、磁盘增长、日志脱敏和告警验证。

## V1.2：入口能力补充

- 验证图片收发。
- 验证 API 文件发送，并扩展 `txt`、`zip` 之外的格式和大小边界。
- 调查 `/api/ws/events` 已连接但未推送新消息的问题，再验证断线重连和重复事件处理。
- 固化文本、文件、群聊和引用消息的请求/响应与错误契约。

## V2：CF Gateway 收口

已完成：

- WeChat Polling、Message Store、身份解析和权限准入。
- Employee Workspace、AIThread、Hermes 调度与线程绑定。
- Hermes 响应回传和 `{"chatId":"...","text":"..."}` 微信文本发送。
- 原始 `isSelf` 解析为 `RawWechatMessage.is_self`，在 normalize/sink 前过滤
  自身消息并推进 checkpoint。

后续工作：

- 将群聊上下文从 V1 whole-room 聚合修正为目标 `bot + group + sender` 隔离。
- 补齐媒体和文件契约、错误映射、限流、超时、重试、幂等和审计。
- 建立长期稳定性、可观测性和生产部署验收。

## V3：Hermes 与 Skills

Hermes API 文本调用、响应回传和线程绑定已经在 V1 Staging 验证。以下能力仍为
后续阶段：

- 图片理解、图片附件传递、文件处理、OCR 和压缩包解析。
- 企业知识库和经授权的 Skills。
- 高风险动作的确认、审批、回滚和审计。
- 生产环境自动部署及端到端生产可靠性验证。

## Known Issue

- VNC 修复和自动重启在验证主机有效，但尚未完整进入仓库部署基线。
- Gateway V1 群聊 whole-room 聚合与目标 `bot + group + sender` 模型存在偏差。
- agent-wechat 的 `txt`、`zip` 入口识别不等于系统文件处理或压缩包解析完成。
