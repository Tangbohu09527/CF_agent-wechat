## 运行时配置差异

### Known Issue：重启策略

当时验证环境的自动恢复使用 `restart: unless-stopped`，但当时实验室 Compose
`docker/docker-compose.yml` 仍是 `restart: "no"`。因此：

- “Debian 重启后自动恢复”只适用于已验证主机配置。
- 直接使用仓库 Compose 不具备同等自动恢复语义。
- 变更仓库默认策略前仍需完成正式配置评审；该轮记录未修改实验室 Compose。

### Known Issue：VNC 修复资产

agent-wechat 默认启动后的 VNC 交互状态不稳定。已验证主机通过以下资产恢复
interactive x11vnc：

- 部署脚本：`docker/fix-vnc.sh`
- systemd unit：`cf-wechat-vnc-fix.service`
- unit 安装位置：`/etc/systemd/system/cf-wechat-vnc-fix.service`

systemd 服务应在 Docker 和目标容器恢复后执行修复，并通过 `systemctl status`、
`journalctl -u` 及实际 VNC 交互共同验收。上述脚本和 unit 当时未纳入本仓库，
新环境不能只依赖仓库文件复现此项验证结论。

## 持久化与认证

| 宿主机路径 | 容器路径 | 内容 |
| --- | --- | --- |
| `./data` | `/data` | `agent.db`、服务状态和内部元数据 |
| `./wechat-home` | `/home/wechat` | 微信账号数据、消息、媒体和缓存 |
| `./secrets/auth-token` | `/data/auth-token` | API 认证及数据库加密 token，只读挂载 |

`data/` 和 `secrets/auth-token` 是同一个恢复单元。已有数据时丢失或替换 token
可能导致数据库无法打开或被重新创建。备份恢复要求见 [operations.md](operations.md)。

## 复核命令

> 以下裸 Compose 与 VNC service 命令只用于复现当时历史实验，已废弃、非当前生产
> 方案，严禁在 CFserver 上执行。生产命令见
> [CFserver 正式部署](deployment/cfserver-production.md)。

```bash
docker version
docker compose version
uname -a
docker compose --env-file .env config
docker compose --env-file .env ps
curl --fail --silent --show-error http://127.0.0.1:6174/health
docker compose --env-file .env logs --tail=200 agent-wechat
systemctl status cf-wechat-vnc-fix.service
journalctl -u cf-wechat-vnc-fix.service -n 100 --no-pager
```

命令输出不得连同 token、联系人或消息内容提交到公开仓库。
