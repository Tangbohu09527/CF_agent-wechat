# 05 V1 验证结果

本文记录 CF_agent-wechat V1 在当前固定测试环境中的实际验证结果。`Verified` 仅表示
本文所列场景已经实测通过，不代表生产可用，也不能外推到其他镜像、系统或部署方式。

## 1. 验证范围

本轮验证覆盖：

- Docker 重启后的容器、健康状态、VNC 和登录恢复流程。
- agent-server 登录状态查询。
- 指定 `chatId` 的文本发送和消息读取。
- 微信侧 `txt`、`zip` 文件消息的识别与 Base64 获取。
- 群聊消息、发送者、群文件和引用上下文读取。
- 群聊合并转发消息的外层识别及内部解析边界。
- `/api/ws/events` 的 WebSocket 连接及新消息事件观察。

本轮没有验证图片发送、通过 API 发送文件、所有文件格式、CF Gateway/Hermes
集成或生产环境可靠性。

## 2. 环境

| 项目 | 已验证环境 |
| --- | --- |
| 操作系统 | Debian 13 Trixie |
| 容器运行时 | Docker |
| 容器 | `agent-wechat` |
| 桌面环境 | XFCE |
| 远程桌面 | noVNC/VNC |

Docker 重启后的实际结果：

| 检查项 | 状态 | 结果 |
| --- | --- | --- |
| 容器自动恢复 | **Verified** | 容器自动恢复运行 |
| Container health | **Verified** | 健康状态正常 |
| noVNC/VNC | **Verified** | 可访问 |
| 微信客户端登录 | **Known Issue** | 需要重新登录 |
| agent-server 登录状态 | **Verified** | 微信重新登录后恢复正常 |

自动恢复结论来自已验证环境配置。仓库当前 Compose 重启策略和 VNC 修复资产仍与
该环境存在差异，不能仅使用仓库默认配置推导出相同结果。

## 3. API 能力

| 方法 | 路径 | 已验证行为 | 状态 |
| --- | --- | --- | --- |
| GET | `/api/status/auth` | 返回当前登录状态和登录用户 | **Verified** |
| POST | `/api/messages/send` | 按 `chatId` 发送文本，返回 `success=true` | **Verified** |
| GET | `/api/messages/{chat_id}` | 读取指定聊天的消息及结构化字段 | **Verified** |
| GET | `/api/messages/{chat_id}` | 读取合并转发消息的外层标题和发送者 | **Verified** |
| GET | `/api/messages/{chat_id}/media/{local_id}` | 获取已识别文件的 Base64 数据 | **Verified**：`txt`、`zip` |
| WebSocket | `/api/ws/events` | 可以建立连接，未观察到新消息事件 | **Pending Investigation** |

`GET /api/status/auth` 的已验证关键字段为：

```json
{
  "status": "logged_in",
  "loggedInUser": "wxid_trx4eew84jvc22_0352"
}
```

以上只记录本次响应中已核对的字段，不代表完整响应 schema 已冻结。

## 4. 消息能力

### 文本发送

`POST /api/messages/send` 已验证支持：

- 指定 `chatId`。
- 发送文本内容。
- 成功响应包含 `success=true`。

### 消息读取

`GET /api/messages/{chat_id}` 已验证可读取以下字段：

- `sender`
- `senderName`
- `content`
- `timestamp`
- `isSelf`

字段存在性已经验证；分页、排序、时间单位和完整错误契约仍未冻结。

## 5. 文件能力

从微信向已验证聊天发送 `txt` 和 `zip` 文件后，API 可识别文件消息：

- 文件消息的 `type=49`。
- 消息包含 `localId`。
- 文件名可从 `filename` 或对应的 `content` 信息取得。

使用下列接口获取文件：

```text
GET /api/messages/{chat_id}/media/{local_id}
```

已验证响应的关键结构为：

```json
{
  "type": "file",
  "data": "<base64>",
  "format": "<format>",
  "filename": "<filename>"
}
```

`txt` 和 `zip` 文件均已成功取得 Base64 数据。此结论仅覆盖微信侧接收、识别和
获取，不表示 `POST /api/messages/send` 已支持文件发送，也不表示所有文件格式均
受支持。

## 6. 群聊能力

已验证群聊支持：

- 使用群 `chatId` 定位聊天。
- 读取群消息。
- 识别消息发送者。
- 识别群文件消息。
- 群消息返回 `isGroup=true`。

## 7. 引用能力

群聊中已验证文本消息引用和文件消息引用。API 返回 `reply` 上下文，已验证关键
结构为：

```json
{
  "reply": {
    "sender": "<sender>",
    "content": "<content>"
  }
}
```

因此调用方可以取得被引用消息的发送者和内容。引用消息 ID、引用层级、已删除消息
和更多富媒体引用结构尚未验证。

## 8. 合并转发消息验证

### 测试场景

微信群中发送微信“合并转发聊天记录”。

### 已支持

通过下列消息 API 可以读取合并转发消息：

```text
GET /api/messages/{chat_id}
```

返回消息的 `type=49`，`content` 为合并转发的外层标题，例如：

```json
{
  "type": 49,
  "content": "罗明贺的聊天记录"
}
```

同时已验证包含以下字段：

- `localId`
- `serverId`
- `sender`
- `senderName`
- `timestamp`
- `isSelf`

这说明 agent-wechat 可以识别合并转发消息外层。

### 未支持

尝试通过下列 media API 获取合并转发内部内容：

```text
GET /api/messages/{chat_id}/media/{local_id}
```

返回：

```json
{
  "type": "unsupported",
  "format": "",
  "filename": ""
}
```

当前 V1 media API 不支持直接解析合并转发内部内容。该返回验证了接口边界，不影响
外层消息识别的已验证结论。

### 当前能力边界

支持：

- 合并转发消息存在性识别。
- 发送者识别。
- 外层标题读取。

不支持：

- 自动展开内部聊天记录。
- 提取内部文本。
- 提取内部文件。

结论：**外层识别已验证，内部解析待增强**。

### 后续增强方向

未来可以通过以下方式实现合并转发展开：

- 微信数据库 XML 解析。
- `refermsg` / `recorditem` 结构解析。
- 独立 forward parser。

## 9. 已知限制

- `/api/ws/events` 可以建立 WebSocket 连接，但本轮未观察到微信新消息事件推送，
  当前状态为 **Pending Investigation**，不得宣称支持实时消息。
- Docker 重启后微信客户端需要重新登录；容器、health 和 VNC 恢复不等于微信账号
  已恢复在线。
- 文件能力只验证了微信侧 `txt`、`zip` 接收与 Base64 获取；API 文件发送、图片
  发送和其他格式仍未验证。
- 合并转发消息只支持外层存在性、发送者和标题识别；内部聊天记录、文本和文件
  尚不能通过当前 V1 media API 解析。
- API 请求/响应 schema、分页、错误码、时间语义和兼容性尚未冻结。
- 仓库 Compose 重启策略及 VNC 修复资产与已验证环境仍有差异。
- CF Gateway、Hermes Agent、幂等、重试、审计和生产可靠性不在本轮验证范围内。

## 10. 后续二开方向

1. 调查 `/api/ws/events` 的订阅条件、事件源、认证、心跳、重连和日志，取得真实新
   消息事件后再评估实时能力。
2. 为文本、文件、群聊和引用消息建立固定样例与契约测试，明确字段可选性和版本
   兼容策略。
3. 解析微信数据库 XML 和 `refermsg` / `recorditem` 结构，建设独立 forward parser。
4. 验证 API 文件发送、图片收发、更多格式、大小限制、失败返回和临时文件清理。
5. 在 CF Gateway 中实现身份映射、授权、幂等、限流、重试、审计和敏感数据脱敏。
6. 将微信重新登录纳入重启后的运维流程，并继续收口自动恢复与 VNC 部署差异。
