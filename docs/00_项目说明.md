# 00 项目说明

## 项目职责

`CF_agent-wechat` 是企业 AI 自动化体系中的微信入口项目，负责：

- 在 CFserver 上运行 WeChat Linux 客户端和 agent-server。
- 保存本项目生产部署、持久化、认证和运行边界。
- 提供微信登录状态检查与登录管理工具。
- 向受信任的调用方提供健康、认证、聊天和消息接口。
- 记录本项目已经完成的实机验证及尚未验证的场景。

本项目不负责：

- `CF_agent-gateway` 的内部身份、权限、路由和业务编排。
- Hermes 或其他 AI 推理服务。
- Skills、ERP 或其他企业系统的业务逻辑。
- 上游 `agent-wechat` 源码维护。

因此，本项目的准确状态是：

> **历史基线上的微信入口、登录管理、消息接口和 Gateway 网络访问已有实机证据；
> 当前 forced fresh QR 生产生命周期已实现并完成自动化验证，但仍需 CFserver
> 真实手机扫码、重启窗口和 Worker heartbeat 验证。**

不得据此推导上层 AI 链路已经完成。

## 当前生产状态

当前批准的生产配置为：

| 项目 | 当前值 |
| --- | --- |
| 正式 Compose | `docker/compose.cfserver.yaml` |
| 正式容器 | `cf-agent-wechat` |
| 显示环境 | 容器内 `DISPLAY=:99` |
| 虚拟显示器 | Xvfb `1280x800x24` |
| 窗口与通知 | fluxbox、dunst |
| 应用 | WeChat Linux 客户端、agent-server |
| 远程桌面 | `ENABLE_VNC=0` |
| Docker 网络 | `cf-internal` |
| Gateway 调用地址 | `http://cf-agent-wechat:6174` |
| 重启策略 | `restart: "no"` |
| 基础准备 | `bootstrap-cfserver.sh`，不登录或启动服务 |
| 唯一生产启动 | `start-qr-login.sh`，每次 fresh runtime 和新二维码 |

VNC、noVNC、x11vnc、websockify、宿主 X11、宿主 XFCE 和 RDP 不属于当前生产
运行方式。正式部署未配置自定义 entrypoint 覆盖，使用镜像默认启动流程。

进程 crash、Docker daemon 重启和 Host 重启均不自动恢复 Agent。Bootstrap 只完成
基础准备；人工 forced-QR 入口归档旧 runtime，创建全新 data/wechat-home，在
auth/chats/messages 全部通过后才放行 `wechat-worker`。

表中 `restart: "no"`、Bootstrap 和 forced fresh QR 是当前批准配置，不属于
2026-08-13 实机证据。历史实机结果在下文单独列出，不能外推为本次生命周期已实机通过。

生产部署和运维命令见
[CFserver 正式部署](deployment/cfserver-production.md)，登录流程见
[微信登录管理](login-management.md)。

## 状态分类

文档统一使用以下四类状态：

- **已实现并实机验证**：已经在记录的 CFserver 生产基线上实际执行并观察到预期结果。
- **已实现但尚未实机验证**：代码或配置入口已存在，但目标现场场景尚未完成闭环。
- **规划中**：尚未形成可按当前生产基线执行和验收的能力。
- **尚未完成生产实机验证**：只表示当前没有生产实机证据，不据此推断实现状态。

历史实验记录只描述当时环境，不自动继承为当前生产验证结论。

## 已实现并实机验证

2026-08-13 已完成：

- 正式 Compose 配置校验、容器运行和健康状态检查。
- `ENABLE_VNC=0`、`DISPLAY=:99`、Xvfb `1280x800x24`。
- Xvfb、fluxbox、dunst、WeChat、agent-server 正常运行。
- x11vnc、websockify 不在生产容器进程中。
- 普通用户执行 `status.sh` 和 `login.sh`。
- `logged_out`、`logged_in`、已登录短路、未登录启动、手机确认、
  WebSocket 登录成功事件及登录后复核。
- Docker socket 无权限时受控回退 `sudo docker inspect`。
- root-only Token 受控读取和普通用户 venv 创建。
- 登录后 90 秒稳定性，健康监控未终止微信进程。
- Gateway 经 `cf-internal` 访问 `/health`、`/api/status/auth`、
  `/api/chats` 和 `/api/messages/{chat_id}`。

完整证据边界见
[2026-08-13 CFserver 生产验证](validation/2026-08-13-cfserver-production.md)。

上述“已登录短路”只属于 2026-08-13 历史基线，不是当前生产行为。当前 forced fresh
QR 流程即使看到 `logged_in` 也不得跳过新二维码。

2026-08-14 追加完成：

- 私聊和群聊文本通过 `POST /api/messages/send` 实际发送到微信。
- 群消息基础字段和 `isMentioned` 的普通消息/真正 @机器人对照。
- 私聊和群聊引用消息的 `type=49` 与 `reply` 结构读取。
- 图片消息 `type=3`、`localId`、`serverId` 和 JPEG media 数据读取。
- 通过 `isSelf` 或机器人发送者信息识别自消息。

这些字段只描述微信消息接口，不承担权限判断、下游防回环或 AI 调度。详细证据见
[2026-08-14 消息与媒体生产验证](validation/2026-08-14-message-media-production.md)。

## 已实现但尚未实机验证

以下登录工具路径已经实现，但尚未在完全新设备上完成实机闭环：

```text
SSH 终端显示二维码
  -> 手机扫码
  -> 手机确认
  -> WebSocket login_success
  -> status=logged_in
```

当前实机通过的是“已信任设备 -> 手机确认 -> 登录成功”。二维码路径不得标为
已验证。

## 规划中或不在本项目边界

以下能力不能从当前生产验证结论推导：

- 镜像升级后的兼容性和长期稳定性验证。
- 实时消息事件能力。
- Gateway、Hermes、Skills 和企业系统内部能力。

这些事项只有在各自项目边界内形成新的脱敏实机记录后，才能写成已验证。

## 安全边界

- 不在 Git、日志、截图或工单中记录 Token、二维码、真实账号、联系人、聊天内容、
  群聊标识或服务器地址。
- Token 目录必须保持 `root:root 700`，Token 文件必须保持 `root:root 600`。
- 不得建议或执行 `chmod 644 auth-token`。
- 6174 端口不得直接暴露到公网。
- `seccomp=unconfined` 和 `SYS_PTRACE` 是当前上游镜像要求，必须持续安全审查。
- CFserver Host 使用 `Asia/Shanghai`；容器和日志使用 UTC。
- 本仓库只协调 `wechat-worker`，不修改 Gateway、PostgreSQL、Checkpoint 或其他仓库。
- 公共示例使用 `<BOT_WECHAT_ACCOUNT_ID>`、`<EMPLOYEE_WECHAT_SENDER_ID>`、
  `<CFSERVER_LAN_IP>` 或 `<AGENT_WECHAT_TOKEN>` 等占位符。
