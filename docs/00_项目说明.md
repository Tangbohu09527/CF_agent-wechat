# 项目说明

## 项目定位

CF_agent-wechat 是 CF 系统的微信入口服务。它在 Debian/Docker 上运行
`agent-wechat`，保存微信客户端和 agent-server 的本地运行态，并向调用方提供健康、认证、
聊天、消息和媒体 API。

本项目负责：

- 生产 Compose、bootstrap、状态和二维码登录脚本；
- 微信登录状态与终端 QR 流程；
- `data`、`wechat-home` 和 `auth-token` 的持久化契约；
- 容器、Docker health、HTTP health 和 auth 的状态检查；
- 服务自身的部署、恢复、测试和运维文档。

本项目不负责：

- Gateway 内部权限、路由、轮询或任务调度；
- AI 推理、上下文管理或业务编排；
- 微信账号策略、人员审批或企业数据治理；
- 主机级备份平台和监控平台的建设。

Gateway 是本服务的调用方。bootstrap 只对其可选代码目录做存在性提示，不启动、停止或
修改 Gateway。

## V1 Beta 生产目标

1. 新 Debian 主机在准备好 Docker、批准代码和镜像 digest 后可运行一次 bootstrap 完成初始化；
2. 容器异常、Docker daemon 或主机重启后自动恢复入口服务；
3. 重启复用原 `data`、`wechat-home` 和 Token，优先恢复原微信会话；
4. 只有 auth 明确需要登录时才显示 fresh QR；
5. 任一步失败保留持久数据和诊断现场，不以清空数据作为恢复手段。

## 生产入口

| 能力 | 入口 |
| --- | --- |
| 初始化和启动 | `scripts/bootstrap-cfserver.sh` |
| 单次状态检查 | `scripts/status.sh` |
| 重启恢复等待 | `scripts/status.sh --wait` |
| 二维码登录 | `scripts/login.sh` |
| Docker 配置 | `docker/compose.cfserver.yaml` |

`docker/docker-compose.yml` 是历史实验配置，不用于生产。

## 持久会话原则

默认持久根为 `/srv/storage/cf-agent-wechat`：

```text
data/                 agent 数据库和服务状态
wechat-home/          微信用户目录和会话
secrets/auth-token    API 认证及数据库关联 Token
```

三项必须作为同一恢复单元备份和还原。Compose 使用 bind mount，因此容器重新创建不会
自动删除这些内容。`restart: unless-stopped` 负责恢复容器，不负责修复丢失或不一致的
宿主数据。

微信会话是否成功恢复由 auth API 决定：

- `logged_in`：继续使用持久会话，不触发登录；
- `logged_out` 或登录等待态：运行 `login.sh` 获取新二维码；
- `app_not_running`：先修复容器/微信进程，扫码不是恢复手段。

## 状态口径

- **代码已实现**：当前工作树存在实现和自动化测试，不等于生产现场已通过；
- **自动化已验证**：测试覆盖特定行为，不等于真实微信、Docker 或主机重启已通过；
- **现场已验证**：必须记录日期、Commit、镜像 digest、环境、动作和脱敏结果；
- **剩余风险**：尚未完成或无法在本仓自动化模拟的生产行为。

当前 hardening 完成后仍需在批准窗口验证：新主机 bootstrap、容器和主机重启、持久 session
恢复、真实手机扫码以及登录失效后的 API 恢复。

## 安全边界

- Token 不进入 `.env`、命令行、日志、工单或版本库；
- 宿主服务默认只绑定 `127.0.0.1:6174`；
- 容器调用方通过 `cf-internal` 使用 `http://cf-agent-wechat:6174`；
- 服务没有 TLS，不直接暴露公网；
- 账号、联系人、聊天 ID、消息正文、二维码和媒体均按敏感数据处理；
- 不使用 `chmod 777`、新 Token 或空 runtime 绕过校验。
