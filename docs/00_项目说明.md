# 00 项目说明

## 项目目标

CF_agent-wechat 是企业 AI 自动化系统的微信入口层。项目使用 agent-wechat 运行
微信账号并提供通信接口，为 CF Gateway 和 Hermes Agent 提供稳定、可验证的微信
接入边界。V1 Staging 已完成微信文本消息到 Hermes 再返回微信的闭环。

## 职责范围

### 负责

- 微信账号运行。
- 消息接收与发送。
- 联系人和聊天管理。
- 图片与文件的入口承接；具体能力以验证结果为准。
- 微信事件转发接口。
- 固定镜像版本、部署基线和验证记录。

### 不负责

- AI 推理与 Agent 决策。
- Skill 执行。
- ERP 或其他企业系统操作。
- 企业身份、权限、审计和业务逻辑。

V1 Staging 中，企业身份、权限、AIThread 和 Hermes 调度由 CF Gateway 承担；
agent-wechat 仍只负责微信接入，不下沉企业业务逻辑。

## 外部依赖

| 项目 | 值 |
| --- | --- |
| 上游 | <https://github.com/thisnick/agent-wechat> |
| 已验证 tag | `0.11.15` |
| 运行镜像 | `ghcr.io/thisnick/agent-wechat:0.11.15` |
| 部署固定方式 | `ghcr.io/thisnick/agent-wechat@sha256:<verified-digest>` |
| 仓库策略 | 不包含、不修改、不再分发上游源码 |

上游许可证和使用授权应由部署方独立确认。真实 digest 记录在受控部署记录中；公开
仓库只保留 digest 占位符，防止把未经复核的值复制到新环境。

## V1 状态

### Verified

- Debian 13 / Docker 环境部署和健康检查。
- Docker 重启后的容器自动恢复、健康状态和 VNC 访问。
- `/api/status/auth` 登录状态查询和按 `chatId` 文本发送。
- 包含发送者、内容、时间等字段的消息读取。
- agent-wechat 入口侧 `txt`、`zip` 文件消息识别和 Base64 获取。
- 群消息、发送者、群文件和文本/文件引用上下文读取。
- V1 Staging 使用 Gateway Polling 完成 Message Store、身份解析、权限准入、
  Employee Workspace、AIThread、Hermes 调用和微信回复回传。
- Gateway 出站请求使用 `{"chatId":"...","text":"..."}`；Polling 层过滤自身消息
  并推进 checkpoint，避免重复调用 Hermes。

### Pending

- 图片理解和图片附件传递。
- 文件消息端到端处理、OCR 和压缩包内容解析。
- 图片发送和通过 API 发送文件。
- WebSocket 实时消息事件；目前只验证了连接建立，未观察到新消息推送。
- 企业知识库、Skill 自动执行和生产环境自动部署。

agent-wechat 对 `txt`、`zip` 的识别和 Base64 获取只代表入口侧能力，不表示系统
已经支持附件传递、文件处理或压缩包解析。

### Known Issue

- VNC 默认启动后的交互状态不稳定，需要额外的 x11vnc 恢复服务。
- VNC 修复资产和已验证的自动重启策略尚未完整反映在仓库部署文件中。
- Docker 重启后微信客户端需要重新登录。
- 群聊目标上下文应按 `bot + group + sender` 隔离；Gateway V1 当前 whole-room
  聚合是已知实现偏差。

具体证据与限制见 [validation.md](validation.md)。
