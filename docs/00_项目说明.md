# 00 项目说明

## 项目职责

`CF_agent-wechat` 是企业 AI 自动化链路的微信入口，负责：

- `agent-wechat` 容器的生产部署边界；
- forced fresh QR 登录生命周期；
- WeChat 进程、认证、聊天与消息 API 的就绪验证；
- Runtime、Archive 与 Token 挂载边界；
- 通过 Gateway Runtime Contract version 1 协调 Poll/Delivery Worker；
- 状态检查、失败隔离和恢复说明。

本仓库不负责 Gateway 的 Message、Admission、Checkpoint、Dispatch、Response、
Delivery 数据模型，不负责 AI 权限、Hermes、Skills、ERP、RAG、OCR、压缩包解析或任意
文件理解，也不维护上游 `agent-wechat` 源码。

## 当前状态

- forced-QR R2 已完成真实 CFserver 验收，当前生产在线。
- 每次 CFserver/Agent 重启、容器重建或人工重新启动都必须使用全新 Runtime 和二维码。
- `cf-agent-wechat` 为 `restart: "no"`，Host reboot 后保持停止。
- 真实 reboot 中 Gateway Poll/Delivery Worker 曾自动恢复；fresh QR 前必须显式关闭并
  确认 Gate，不能依赖 automatic boot stop gate。
- PR #1 与 PR #4 仍为 stacked open PR，R2 尚未提升到 `main`。

详细 SHA、容器、路径、镜像和限制只见 [当前生产状态](production-status.md)。

## 运行边界

```text
Host / Docker
  -> cf-agent-wechat
       -> internal Xvfb
       -> /usr/bin/wechat
       -> agent-server :6174
  -> external cf-internal
  -> CF_agent-gateway Poll/Delivery
  -> Hermes
```

- 6174 仅绑定 Host loopback；Gateway 通过 `cf-internal` 访问。
- VNC/noVNC、宿主 X11、XFCE 与 RDP 不在生产路径。
- Docker health、WeChat auth 与 Gateway readiness 是不同层级。
- Gateway-only 部署若不重启或删除 Agent，Session 可以保持；Agent 自身重启必须 fresh QR。

## 生命周期入口

| 入口 | 职责 |
| --- | --- |
| `sudo ./scripts/bootstrap-cfserver.sh` | 只准备和校验部署输入 |
| `./scripts/start-qr-login.sh` | 唯一生产启动与 fresh QR |
| `./scripts/stop-qr-runtime.sh` | 停止 Worker 与 Agent，保留数据 |
| `./scripts/status.sh` | 只读完整在线判定 |
| `./scripts/login.sh` | 兼容转入唯一启动入口 |

详细命令只见 [CFserver 生产 Runbook](deployment/cfserver-production.md)。

## 当前限制

- CFserver reboot 后需要人工 fresh QR，离线消息可能无法补拉。
- automatic Gateway boot stop gate 未证明。
- Archive 不得恢复为 active Session，并按受限敏感资产管理。
- 上游 API/schema 可能变化，`seccomp=unconfined` 与 `SYS_PTRACE` 需持续审查。
- 现场 Image ID 与源码 SHA 的精确映射未验证。
- 本仓库不保证 Gateway、Hermes、数据库或业务自动化恢复。
