# 00 项目说明

## 项目定位

`CF_agent-wechat` 是企业 AI 自动化系统的微信入口层。它负责运行 WeChat Linux
客户端和 agent-server，把微信侧登录、聊天和消息能力以受控接口提供给上层调用方。

本项目不是 Gateway，也不负责任务调度。两者的关系是：

- Gateway 通过 `cf-internal` 调用本项目的 agent-server；
- 本项目的 forced-QR 启动脚本只控制 Gateway `wechat-worker` 的停止和启动顺序；
- Gateway 内部权限、队列、轮询、任务编排和数据库不属于本项目。

## 职责边界

| 本项目负责 | 本项目不负责 |
| --- | --- |
| 微信容器、虚拟显示和 agent-server | AI 推理与模型服务 |
| forced-QR 登录和状态判定 | Gateway 内部权限与任务调度 |
| runtime 轮换、归档保护和 Token 隔离 | Gateway/Hermes 数据库维护 |
| 健康、认证、聊天、消息和 media 接口 | 企业业务规则、Skills、ERP |
| worker 放行前的入口侧验证 | 外部归档删除、备份平台和容量监控 |
| 本项目部署、运维、验证与排障文档 | 上游镜像源码维护 |

## 两个生产基线

### 历史实机基线

2026-08-13/14 的 CFserver 记录证明了当时版本上的：

- 容器、Xvfb、WeChat、agent-server 和无 VNC 链路；
- 已信任设备的手机确认登录和登录状态管理；
- Gateway 对健康、认证、聊天和消息端点的访问；
- 文本发送、群消息字段、引用结构和图片 media 读取。

该基线会恢复或复用旧会话，不能证明新的 forced-QR 生命周期。

### forced-QR 目标基线

同仓特性分支已实现：

```text
stop worker
  -> archive old runtime
  -> create fresh runtime
  -> start container
  -> render fresh QR in SSH
  -> scan and confirm
  -> verify process + auth + chats + messages
  -> start worker
```

## 状态分类

- **已完成**：目标分支存在实现入口。
- **已验证（自动化）**：本仓测试在隔离环境覆盖预期行为，不连接真实微信或 CFserver。
- **已验证（CFserver 实机）**：带日期记录在真实主机执行并观察到预期结果。
- **未验证**：缺少目标环境现场证据，不能从旧基线或自动化结果外推。
- **后续规划**：生产合入、现场验收或外部治理动作，尚未成为当前可承诺能力。

当前明细统一见 [验证总览](validation.md)。

## 数据与安全边界

目标存储布局：

```text
/srv/storage/cf-agent-wechat/
├── runtime/
│   ├── data/
│   └── wechat-home/
├── session-archive/
│   └── <UTC时间戳>/
└── secrets/
    └── auth-token
```

- Token 不属于 runtime，不得进入归档、manifest、环境变量、日志或命令行。
- secrets 目录保持 `root:root 700`，Token 保持 `root:root 600`。
- runtime 与 archive 必须满足脚本的同文件系统原子移动检查。
- 脚本不自动删除历史归档；容量、期限与审批删除属于外部运维策略。
- 6174 只允许受控宿主绑定和 `cf-internal` 访问，不得暴露公网。
